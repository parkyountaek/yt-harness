# yt-harness repository rules

- Design notes are kept locally on each machine and are never committed.
- Everything in this repository is written in English.
- This repository holds the shared skeleton only. Anything produced by work on a specific machine stays in `~/yt-local/`.
- Only paths listed in `allowlist.txt` may be committed. The hooks in `.githooks/` enforce this; enable them with `git config core.hooksPath .githooks`.
- Neutral sources (`AGENTS.md`, `procedures/`, `harness.yaml`, `yt-core/plugin.yaml`, `bin/`) are the originals. Runtime-specific files (plugin manifests, marketplaces) are generated by `yt-core/bin/yt-build`; do not edit them by hand.
- Claude and Codex must pass the same contract tests (`tests/contract/run.py`). Hard constraints live in neutral layers (scripts, git hooks, the shared `sandbox-exec` profile), not in runtime features.
- Keep every instruction file (this file, `SKILL.md`, plugin agents, the generated work order) under 200 lines. Move detail into scripts or referenced files instead of growing instructions.
- `mods/` holds Claude interface mods for the human's own sessions (status band, alerts, compaction notes). Their `plugin.json` is hand-written. They never load in sub-sessions (`launch.claude_isolation`) and are not part of runtime parity, so nothing a work order depends on may live there.
