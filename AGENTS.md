# yt-harness repository rules

- Everything in this repository is written in English.
- Only paths in `allowlist.txt` may be committed; `.githooks/` enforces it (`git config core.hooksPath .githooks`). Machine-specific content stays in `~/yt-local/`.
- Neutral sources (`AGENTS.md`, `procedures/`, `harness.yaml`, `yt-core/plugin.yaml`, `bin/`) are the originals. Plugin manifests and marketplaces are generated by `yt-core/bin/yt-build`; never edit them by hand.
- Claude and Codex must pass the same contract tests (`tests/contract/run.py`). Hard constraints live in neutral layers (scripts, hooks, the sandbox profile), not in runtime features.
- Keep instruction files (this file, `SKILL.md`, plugin agents, the work order) under 200 lines, and keep in them only what the model cannot infer and nothing enforces: move the rest into scripts, hooks, or referenced files.
- `mods/` holds Claude interface mods for the human's own sessions only (hand-written `plugin.json`). They never load in sub-sessions, so nothing a work order depends on may live there.
