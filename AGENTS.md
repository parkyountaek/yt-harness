# yt-harness repository rules

- Design notes are kept locally on each machine and are never committed.
- Everything in this repository is written in English.
- This repository holds the shared skeleton only. Anything produced by work on a specific machine stays in `~/yt-local/`.
- Only paths listed in `allowlist.txt` may be committed. The hooks in `.githooks/` enforce this; enable them with `git config core.hooksPath .githooks`.
- Neutral sources (`AGENTS.md`, `procedures/`, `harness.yaml`, `bin/`) are the originals. Runtime-specific files are generated by `yt-build`; do not edit them by hand.
- Claude and Codex must pass the same contract tests. Hard constraints live in neutral layers (scripts, git hooks, the shared `sandbox-exec` profile), not in runtime features.
- Keep every instruction file (this file, `SKILL.md`, plugin agents, the generated work order) under 200 lines. Move detail into scripts or referenced files instead of growing instructions.
